## D 批迁移

`004_recommendation_delivery_feedback.mysql.sql` 在完整 C 批 17 表结构上执行一次，新增 `recommendation_feedbacks` 并为既有 `recommendations` 增加承接、准备、版本、共享依据和固定快照字段，业务表总数为 18。先将 `preflight_d.preflight(connection)` 用在明确指定的隔离库连接上；脚本不加载项目配置或 `.env`。预检检查原始 17 表、旧唯一索引、推荐/简历/沟通/用户外键孤儿及旧推荐状态，返回旧行数和缺少提交元数据的历史交付计数，不读取客户内容或凭据。缺少的历史提交元数据仅作核验提示，迁移保留原值且不推断补齐。

迁移保留全部推荐、沟通及旧反馈字段，不推断旧承接关系、共享同意、简历版本、固定交付快照或反馈作者/时间。旧推荐的新增字段保持 NULL，按“历史待核验”处理；新唯一键允许多个 assignment_id 为 NULL 的历史行。`status` 显式加入 `accepted`。MySQL DDL 可能隐式提交；迁移前停写并验证备份，部分执行失败后停写记录最后完成的语句，按核验后的语句续修或恢复备份，不盲目重跑文件，也不依赖单次 `ROLLBACK`。

D 批隔离演练脚本 `validate_mysql_d.py` 只启动新建本机临时 MySQL 实例、使用合成数据及进程内随机密码，依次运行 001→004 并在退出时关闭服务；不读取项目 `.env` 或连接正式库。验收结果写入 workspace 根目录 `mysql_D验证结果.json`。OpenAPI 由 `export_openapi_d.py` 直接导出真实注册路由，不启动应用或连接数据库。

## C 批迁移

`003_resume_skills_match.mysql.sql` 只在完成 B 批的隔离 MySQL 8.0.16+ 库中执行一次。新增 skills/resume_skills，15→17 张业务表；给旧简历按 candidate_id、created_at、id 编版本，多主标记只留最新的原主简历。保留全部文件路径、正文及匹配历史；不造上传人、旧需求版本或输入快照。

简历正文与模型输出字段使用 MEDIUMTEXT，承载 50000 字符正文及有界模型返回，避免中文 UTF-8 字节数超出普通 TEXT 的 65535 字节限制；SQLite 仍采用 Text。迁移只扩大容量，不改写历史正文。

执行前停写、验证数据库与私有附件联合备份、调用 `preflight_c.preflight(connection)` 只读核验（不加载配置、不自动选库），并检查完整 B 结构。异常引用/分数先停止，不截断或删除历史；正文成功但为空的异常计数登记，应用不允许用其新建匹配。SQL 自带无持久 DDL 的历史数据 guard；部分执行后不得直接重跑。

新文件只在私有目录，经权限下载。历史绝对路径也必须位于已配置私有根目录，外部路径不会自动开放；旧文件需要在未来正式部署窗口由操作者核对搬迁与更新引用，不能因副本未复制文件宣称正式文件丢失。文件摘要/上传人未知时可空。

MySQL DDL 隐式提交，失败保持停写，按语句记录修复续行或已验证备份恢复。新业务源码须与迁移配套部署；不靠应用启动 create_all 升级旧表。本批验证脚本、计数结果和恢复演练以 C 批验收报告为准，以下 A/B 内容保留为历史。

## 执行与恢复

SQL 是一次性顺序脚本，不是可任意重复执行的幂等迁移器。MySQL DDL 有隐式提交；中途失败不能使用一个 ROLLBACK 撤销全部变更。记录最后成功语句，保持停写，检查结构后修复续行，或从已验证备份恢复。不要直接重跑整文件，也不要 DROP 新表丢弃已产生的数据。

历史 created_by 指向猎头时回填个人主体和负责人；空建档人或非猎头建档记录不开放。账号被禁用时允许保留其历史归属，但接口仍拒绝访问。不会自动建机构、猜测企业关联或生成客户授权。

完成后验证 12 张业务表、两个候选人归属外键、机构成员生成列唯一约束、服务主体 XOR CHECK，以及回填结果。候选人 created_by 和历史匹配内容不应被修改。
